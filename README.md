# Echo

Echo is a reflection system for user-described dreams. A user shares a dream in their own words, and Echo responds with brief, presence-based reflections. It does not interpret dreams symbolically, assign meaning, or provide explanations, and it avoids advice, reassurance, and emotional dependency.

Reflections are generated by a cloud LLM (Groq, model `qwen/qwen3.8-27b` by default, overridable with `GROQ_MODEL`). Voice output is generated with Edge TTS and routed deterministically: `she` → `en-US-JennyNeural`, `he` → `en-IN-PrabhatNeural`. There is no automatic voice detection and no browser-side fallback.

## What Echo is not

- Not a dream interpretation system
- Not a therapist or mental health tool
- Not a conversational assistant
- Not an emotional companion
- Not an advice or recommendation system

Echo is intentionally constrained by design.

## Running it

```bash
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt
echo GROQ_API_KEY=your_key_here > ../.env
.venv/Scripts/python -m uvicorn api.routes:app --port 8000
```

Then open http://localhost:8000/ (redirects to `/ui/`). `GET /llm-test` is a smoke test for the Groq connection.

`.env` holds the API key and is gitignored — never commit it.

## Deploying

`render.yaml` describes a single Render web service that runs the whole app (API and UI together). Create it with Render's Blueprint flow, then set `GROQ_API_KEY` in the dashboard — it is deliberately not stored in the blueprint.

All filesystem paths are anchored to their own module, so the server can start from any working directory. Render's start command uses `uvicorn --app-dir backend` from the repo root.

Vercel is not a fit: it serves the static frontend only, its functions cannot persist the generated MP3s between requests, and the Hobby timeout is shorter than one dream takes.
